# 决策安全沙箱机制（Decision Security Sandbox）

在智能体的工具调用**真正落地之前**，对该决策做安全研判与控制。沙箱 = **风险体系（静态） × 态势感知（动态） × 影子执行（预测）**。

## 四类研判动作

| 动作 | 触发条件（示意） | 效果 |
|---|---|---|
| **放行** | 低风险 / 可逆 / 与任务目标一致 | 直接执行 |
| **二次确认** | 中高风险但可能合理 | 要求确认 / 补充依据后执行 |
| **拦截** | 高危且明显越权 / 偏离 / 被劫持 | 阻断执行并告警 |
| **降级** | 高危但任务需要 | 以更安全的等价方式执行（如 dry-run / 限定范围 / 影子预演） |

## 混合研判引擎

"**规则引擎 + 大模型研判（LLM Judge）**"双层：

- **规则**：基于[风险体系](agent-decision-risk-taxonomy.md)的确定性策略（如"不可逆 + 批量 + 高危 → 默认拦截"），覆盖面广、可解释、低延迟。
- **LLM Judge**：对规则难以覆盖的语境化决策（是否偏离任务目标、是否被注入劫持）做语义研判，复用 [Optima-Bench](optima-bench.md) 的 LLM Judge / golden-state 对比思路。

## 态势感知输入（动态）

沙箱研判不只看单步命令，还看**会话态势**：当前累计风险暴露、近期是否出现异常行为序列（短时批量破坏、目标偏移、重复试探）。态势特征来自智能体—工具之间的观测层与调用轨迹（call trace）。

## 影子执行（Shadow Execution，预测）

对**高危且不可逆**的决策，先在镜像 **Mock 状态**中预演该工具调用：预测它会造成的状态变更与危害后果，评估后再决定是否落到真实工具。这是对 [Optima-Bench](optima-bench.md) 拦截式 Mock 执行器与 golden-state 对比机制的**安全化升级**——把"评测时的状态预演"变成"防御时的危害预测"。

## 设计目标

在**有效拦截危害**的同时**尽量不损害正常任务效用**——这对 false-block（误拦）与 utility retention（效用保持）提出量化要求，见 [研究计划与考核指标](../analyses/2026-05-30-research-plan-and-kpis.md)。
